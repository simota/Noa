# Scrollback persistence (record view)

**Status: implemented (Stage 0 + Stage 1). GUI visual check not done.**
Q1 / Q2 are answered; Q3–Q5 were implemented with provisional decisions (§10 Decisions). Deviations
and reductions fixed during implementation are recorded in §12.
Provenance: synthetic (`synthetic: true`). It started from a request by a synthetic persona
generated by Plea, "Hina (27) / continuing beginner / personal Mac". It is not a verified
voice of a real user. Remember that the demand itself is a hypothesis whenever priority is decided.

## 1. Problem

`docs/specs/session-restore.md` restores only the topology (windows / tabs / splits) and
the cwd. It specifies that terminal content is "not restored, to match Ghostty".
That is correct as a spec, but it has a side effect: because the UI is restored, users
expect the content to be restored too.

> All the tabs came back exactly as they were, so I thought "oh, I can keep reading". But
> when I opened one it was blank. So what was restored? What I wanted to see wasn't the layout,
> it was the error text...

There are two independent defects here. Do not mix them in discussion:

| # | Defect | Kind | Response |
|---|--------|------|----------|
| D-1 | What is restored and what is not is communicated neither before nor after | Lack of honesty (close to a bug in today's code) | Stage 0 |
| D-2 | The content that was last on screen is itself lost | Missing feature | Stage 1–2 |

D-1 can be resolved on its own without implementing D-2, at an order of magnitude lower
cost. Fix D-1 first.

### Acceptance criteria mapping

| AC (user view) | Stage that satisfies it |
|---|---|
| After quit → launch, the last on-screen content of each tab can be read | Stage 1 (history tail) |
| If the content will not come back, that is known in advance | Stage 0 |
| Live and record can be told apart | Stage 1 (record view) |

## 2. Premises and assumptions (explicit)

- A-1: The demand is synthetic. It is a hypothesis from one persona; how often real users ask for this is unknown.
- A-2: The "error text" Hina wanted to read is assumed to be on the primary screen.
  Display inside an alt screen (vim / less, etc.) is out of scope for this proposal (see §6).
- A-3: The assumed environment is a personally owned, single-user Mac. Shared machines,
  managed terminals and multi-user threat models are out of scope for v1.
- A-4: Restoring across machines (sync) is out of scope.
- ~~A-5: The granularity of "the last on-screen content" cannot be fixed from the request text~~ → resolved by Q2.
  The target is the whole history (the tail). No one-screen mode is built (§10 DEC-2).

## 4. Design approach

### 4.1 What to save (not "replay bytes" but "rendered rows")

| Option | Content | Verdict |
|---|---|---|
| (a) Save the pty byte stream and feed it back into `Stream` at startup | Most faithful | Rejected. Side effects are replayed (OSC 7 cwd overwrite, title changes, bell, kitty gfx, alt screen transitions). Size is unbounded. Restore is slow |
| (b) Save the rendered rows (cells + attrs) | Deterministic, zero side effects, bounded by row count | Adopted |
| (c) Plain text only | Cheapest | Rejected on its own. Once colour is lost, "red = error", a beginner's only clue, disappears. Kept only as the degraded path of Stage 1 |

Correction made during implementation: the original plan was to "serialize the packed representation
as-is", but this turned out to be impossible. Two ids in the packed representation are
*process*-scoped. `GraphemeId` is an index into a global `LazyLock` interner, and `HyperlinkId` is an
index into `Terminal::hyperlinks`. If either is written to disk, the next process decodes it to
different text. The format therefore works at the materialized `Row`/`Cell` level: it resolves both to
content (the cluster's bytes, the link's URI) and re-assigns ids on load. Styles are re-interned per
snapshot, and deflate reclaims the rest.

### 4.2 Scope of what is saved

- Primary screen only. An alt screen is a temporary display by definition and is not saved.
  For a pane that was on an alt screen at exit, the primary history underneath it is restored.
- From the tail. Keep the newest side, not the head (what Hina wants to read is "the last of it").
- Per pane. Each leaf of a split has its own independent snapshot.
- Excluded: the scratch terminal (throwaway popup / `docs/specs/scratch-terminal.md`)
  is never saved. Remote attach panes (`RemotePane`) are also not saved in v1
  (the owner of the content is not local).

### 4.3 Capacity limits

Layered caps make runaway growth structurally impossible:

| Cap | Default | Unit | Purpose |
|---|---|---|---|
| `scrollback-persist-limit` | 1 MiB | Bytes after encoding, before deflate, per pane | Upper bound on the saved tail. This is the only quantity knob (someone who wants one screen sets it small). It is measured before compression because that is the only quantity for which the capture side can fix the budget without compressing twice. The file on disk is always smaller than this |
| `scrollback-persist-total-limit` | 64 MiB | Actual file size, total | Total disk usage. Checked by actual size at startup; when exceeded, files are dropped in order of oldest mtime |
| `scrollback-persist-max-age-days` | 7 | Days (integer) | Automatic expiry of old records. `0` means no expiry. noa's config has no suffix syntax, so `7d` is a diagnostic error |

In addition, GC at startup: snapshot files not referenced from `session.json` are
deleted (orphan collection).

### 4.4 When to write (not the same as session.json)

`persist_session()` runs on every topology change. Running a copy of up to 1 MiB per pane
at that frequency is out of the question. The snapshot trigger is separate:

1. At clean exit (winit `exiting`): the main path.
2. Idle checkpoint: when output has been quiet for 5 seconds, capture only the panes that have
   produced output since the previous checkpoint. If quiet were the only condition, it would
   *never run as long as output does not stop* (exactly the long build whose tail we want to keep), so
   60 seconds since the previous checkpoint is the upper bound, and it runs at least once even during a flood.
   Crash tolerance comes from here.
3. Explicit command: command palette `Checkpoint Scrollback Now`.

Capture (reading `Arc<Mutex<Terminal>>` + encoding) runs on the main thread;
disk writes run on a dedicated worker (`scrollback_persist::ScrollbackPersister`).
It coalesces per key, so even if checkpoints for 10 panes overlap, only each pane's
latest bytes are written.

### 4.5 File format

`<data-dir>/noa/scrollback/<pane-key>.nsb` (on macOS,
`~/Library/Application Support/noa/scrollback/`). One field, `"scrollback": "<pane-key>"`, is added to a leaf of
`session.json` (`SESSION_VERSION` goes 2 → 3; 2 was already used for remote metadata). The pane-key is limited to 16 lowercase hex digits. Since `session.json` is an editable file, it is treated as an entry point for path traversal and validated.
**A version mismatch, corruption or absence falls back to "no record" only and does not block startup**
(the same convention as the existing session.json).

```
magic   "NOASB\0"        6 B
version u16              = 1
flags   u16              bit0: deflate, bit1: encrypted
cols    u32              grid width at save time (for the reflow decision)
saved_at u64             Unix seconds (used for the record view's label)
rows    u32              row count
payload …                deflate(style table ++ link table ++ grapheme table ++ rows)
```

serde is not used (to match the hand-written parser convention of `noa-config` / `session.rs`).

### 4.6 Encryption and permissions ← the heaviest decision in this proposal

Terminal scrollback routinely contains sensitive information: `export AWS_SECRET_ACCESS_KEY=…`,
tokens echoed by a CLI, `git remote` URLs containing a PAT, private source. Today that
exists only in RAM and disappears with the process. Persistence changes this threat model.
This is not a change to turn on by default just because it is convenient.

**v1 baseline (required from Stage 1):**

- Directory `0700`, files `0600`.
- The save location is already under the user-scoped Application Support (under FileVault protection).
- Exclude from Time Machine / iCloud backup
  (`NSURLIsExcludedFromBackupKey`). This closes the path by which records leak out via backups.
- When `scrollback-persist = never` (default), the directory is not created at all.

**Stage 2 additions (opt-in):**

- `scrollback-persist-encrypt = true` enables AES-256-GCM. The key is in the Keychain
  (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`). A nonce per file.
- If the key cannot be obtained, decryption is abandoned and it falls back to "no record" (startup is not stopped).

Default OFF is final (§10 DEC-1). noa is a faithful clone of Ghostty, and Ghostty does not
restore content. Default ON would be a deviation in observable behaviour. This feature is
therefore an explicit noa extension, default `never`. The intent of AC-1 is guaranteed by Stage 0. By providing a path
that shows how to enable it "at the very moment of disappointment", we keep opt-in from
becoming a "feature nobody notices". Without that path, Stage 1 has no value (this is why the §7 order
is fixed).

## 5. Record view (the answer to AC-3, "live / record distinction")

If restored rows are simply poured into scrollback, past output looks like live output.
That would reproduce the original defect (D-1) in another place. The restored region is therefore
presented as an explicitly marked read-only band.

```
  │ $ cargo build
  │ error[E0308]: mismatched types      ← record (left gutter: light accent rule)
  │   --> src/main.rs:42:9
  ├──── record · saved 2026-07-28 14:03 · live below ────
    $ ▏                                   ← live (no gutter)
```

- Separator row: a full-width light rule + a saved-time label. A synthetic row that does not come from the pty.
- Left gutter: a background rectangle in a light accent colour in column 0 of each row of the record region
  (see §12 D-2 for the implementation deviation). No dimming (what Hina wants to read is those
  characters, and making them harder to read would defeat the purpose). Selection, search hits and the cursor take priority over the gutter.
- ~~"Record" badge~~ → dropped (§12 D-3).
- The record region is ordinary scrollback, so selection, copy and search work as they are.
- In the record region, shell integration semantics (re-running via prompt jump, etc.) are
  disabled. OSC 8 links stay enabled.
- Ways to discard: command palette `Discard restored history`. `clear` also removes it.

## 6. Non-goals

- Restoring running processes. What is restored is dead text, and the shell is new.
- Replacing logging (not a substitute for `script` / tmux logging).
- Restoring alt screen content (vim / less / TUI screens).
- Restoring kitty graphics / sixel. In Stage 1–2 image cells are dropped and
  replaced with a one-line placeholder (so that we do not also erase the fact that "an image was there").
- Sync between machines.

## 9. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Sensitive information stays on disk | High | Default OFF, `0600`/`0700`, backup exclusion, encryption in Stage 2 (implemented). A warning is shown once when enabled |
| Window width at restore differs from save time | Medium | Save `Row::wrapped` and `cols`, and pass them through `screen/reflow.rs` |
| Capture at exit makes quit slow | Medium | The cap bounds the worst case. `exiting` already waits for the persister's flush |
| Eats up disk | Medium | Three-layer cap (§4.3) + startup GC |
| Record mistaken for live | Medium | The record view in §5. Cutting it takes us back to the original defect |
| Deviation from Ghostty parity | Low | Default OFF + recorded as an explicit deviation in the Parity Map |

## 10. Decisions

| # | Decision | Rationale | Status |
|---|---|---|---|
| DEC-1 | Default is `scrollback-persist = never` (opt-in) | Answer to Q1. Keeps Ghostty parity. Persistence changes the threat model, so it is not default ON | Final |
| DEC-2 | What is saved is the tail of the whole history. No one-screen mode (`screen`) is built | Answer to Q2. The amount is controlled by `scrollback-persist-limit` alone, and there is no reason to have two paths (`screen` is just a "small `tail`") | Final |
| DEC-3 | v1 protection is FileVault + `0700`/`0600` + backup exclusion. Keychain encryption is opt-in in Stage 2 | Q3 is unanswered, so the recommended value from §4.6 is adopted. Premise is A-3 (a personally owned, single-user Mac) | Provisional |
| DEC-4 | The restored record is kept. It does not disappear when live output arrives (same lifetime as ordinary scrollback). Discarding is explicit, from the command palette `Discard restored history` and from `clear` | Q4 is unanswered. Having it disappear on its own is the bigger surprise, and "being able to go back and read" is the request itself | Provisional |
| DEC-5 | The save unit is the pane (each leaf of a split is independent) | Q5 is unanswered. Shrinking it to per-tab would create an asymmetry of the same type as the original defect (D-1): "restored, but only one split is empty". The total is held down by the three-layer cap in §4.3 | Provisional |

DEC-3 / 4 / 5 are provisional. If there is an objection before implementation starts, they will be replaced.

## 11. Manual verification (Stage 1)

0. Launch with the default (key unset) → no record is restored, and the restored tab shows the
   Stage 0 notice line. It must be possible to read from it how to enable the feature.
1. Set `scrollback-persist = tail` and run `cargo run -p noa`. Open a few tabs, cause a
   build error in one, and scroll enough. `cmd+q` → relaunch.
2. In that tab, the error text is restored in colour, with the record separator + left gutter.
   There is a live prompt below. Scrolling up goes back through history up to the limit.
   The restored region matches a search (`cmd+f`).
3. Change the window width and relaunch → wrapped lines reflow correctly.
4. Set `scrollback-persist = never` again and relaunch → no record is restored, and
   `~/Library/Application Support/noa/scrollback/` is empty (or not created).
   `Discard restored history` removes only the record region, and the live side is intact.
5. Corrupt a snapshot file → normal startup, no record, no error.
6. Open a scratch terminal and quit → no record is created for that pane.
7. Check permissions `0600` and the backup-exclusion attribute with `ls -l@`.

## 12. Deviations fixed during implementation (differences from the proposal)

Points that could not be built, or were not built, as proposed. Kept with reasons.

| # | Proposal | Implementation | Reason |
|---|---|---|---|
| D-1 | Serialize the packed scrollback representation as-is | Serialize materialized `Row`/`Cell` in a custom format | `GraphemeId` / `HyperlinkId` in the packed representation are process-scoped. Written to disk, they decode to different text in the next process (§4.1) |
| D-2 | A 1px vertical rule at the left of the record region | A background rectangle of one cell in column 0 | A sub-cell-width rectangle needs a new GPU primitive (shader / vertex layout change). That is exactly the area the GPU gotchas section of `CLAUDE.md` explicitly warns about, and the readability of the boundary is not lost at cell granularity. One rectangle per row, riding on the same existing path as the selection background |
| D-3 | A "record" badge while the viewport overlaps the record region | Not implemented | The badge goes through the native AppKit overlay path (same as the scratch badge), and the cost does not match the goal of marking the boundary. The separator row carries its own label (`record · saved <time> · live below`), and entering the record region always crosses that row, so the distinction holds. The badge is a follow-up once it is confirmed to be wanted |
| D-4 | `scrollback-persist-max-age = 7d` | `scrollback-persist-max-age-days = 7` | noa's config has no suffix syntax anywhere (`cursor-stop-blinking-after` and `background-image-interval` are both plain integer seconds). Expressing the unit in the key name is the existing convention |
| D-5 | The per-pane limit is "bytes after compression" | "Bytes after encoding, before deflate" | To cut the budget after compression you would have to cut, compress, and redo on overflow. Before compression it is fixed in one pass, and compression only ever makes the result smaller than promised |
| D-6 | `SESSION_VERSION` to 2 | To 3 | 2 was already used for remote pane metadata |
| D-7 | (not in the proposal) | Discarding the record is implemented by rebuilding the existing scrollback | Pages are immutable once packed and are evicted only per page. `erase_display(Scrollback)` would also erase the live history, so an O(n) path was added that materializes the remaining rows and packs them again. It is a rare user-initiated command, so the bulk-output hot path is untouched |
| D-8 | The record region's gutter range is always valid | Only the marking is dropped when coordinates have been renumbered | `record_rows`/`annotation_row` are caches of absolute rows, and column-count reflow and scrollback clear renumber the whole space. `Terminal::grid_coordinate_generation` is bumped on exactly those two and not on ordinary eviction (guaranteed by an existing test), so comparing against it is a complete staleness check. On mismatch the gutter, `skip_row` and Discard are stopped. A missing mark is far lighter than erasing the wrong rows. The boundary itself is the separator row (= content), so it survives reflow and AC-3 is kept |
| D-9 | (not in the proposal) | Persisted links are cut off at 4 KiB | The OSC 8 payload limit is the parser's 12 MiB. Links go in a side table and are invisible to the per-row budget calculation, so a single URI could break through the whole snapshot's limit. Nobody follows a URL longer than this, so the cell characters are kept and only the link is dropped |
| D-10 | `scrollback-persist-max-age-days` bounds the age of the record content | It bounds the age of the file | A pane that stays in use is recaptured at every exit and carries over the restored record, so the file's mtime keeps being updated. Bounding the age of the content needs a per-row timestamp, which would be a format change. We chose to state the meaning of the key explicitly in `CONFIGURATION.md`. Bounding the amount is the job of `scrollback-persist-limit` |
| D-11 | A restored pane inherits the key it was saved with | A new key is issued at restore, and the old file is deleted when the first capture succeeds | If two noa processes restore the same session, they fight over the same file. Issuing a new key avoids the collision. The old file is deleted not "at restore" but "when my own first write has finished", so that a record to return to remains if a crash happens in between. In steady state there is one file per pane (confirmed over 4 generations on a real machine) |
| D-12 | The key is `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` | Non-synchronizable (`kSecAttrSynchronizable = false`) + the login keychain's default accessibility | `security-framework` 3.7 does not expose `kSecAttrAccessible` (there is no setter in `PasswordOptions`). A generic password in the login keychain is readable only while unlocked to begin with, and sync is explicitly turned off, so the intent is met. Specifying the exact constant would require touching a deprecated raw query field, which is not worth it |

### Stage 2 implementation status

- Implemented: `scrollback-persist-encrypt` (AES-256-GCM + login keychain). The outer container
  `NOAEN` wraps the `noa-grid` format, so the grid side knows nothing about encryption. Reads branch on
  the file itself rather than on the setting, so toggling ON/OFF never makes existing files
  unreadable. When the key cannot be obtained, the write is skipped instead of writing plaintext.
- Implemented: placeholder replacement (`[image]`) for kitty graphics / sixel. The image data is not
  persisted and does not exist in the next process, so saving it as-is would restore a column of tofu.
  Dropping it silently would also erase the fact that "something was there".
- Not done: the record badge remains unimplemented. `draw_toast_card` is a centered
  toast that takes no position, and a permanent badge needs new drawing and placement code. The judgment
  was that adding a visual element that cannot be verified to the drawing layer, which has many GPU traps, while screen-recording
  permission has lapsed and visual verification is impossible, does not pay off. The boundary display itself
  holds through the separator row (D-3).
- Not done: the prepend at startup itself is still on the main thread. Loading and inflate were
  moved up in parallel, but inserting into scrollback touches `Terminal`, so it remains.

### Review findings rejected

- Switch trailing-whitespace trimming to `Row::occupied()`: it looks right at first glance, but restored rows
  come from `Row::from_cells` and have `occ == cells.len()` (a conservative watermark).
  Using `occupied()` as the basis would make a recapture of a restored pane encode every column,
  bloating the snapshot. Cells with default values are inert both visually and semantically, so the
  value comparison stays.
